# badbatch

A product recall for agent work, where every artifact is stamped at creation with the agent, prompt version, and model that made it, and one command walks that stamp graph to enumerate everything a bad batch ever touched.

## What this is

Version control can revert commits and nothing else, and nobody tracks which agent, prompt, and model produced which change across files, tickets, messages, docs, and API calls, so the downstream effects of a bad batch cannot be enumerated from the records most teams keep. Badbatch starts at the stamp, a provenance record written when work is produced, naming the agent, the prompt hash, the model version, and the parent artifacts it derived from. The stamp command prints that stamp for one recorded run record. The recall command walks the stamp graph from one or more stamped files and lists every downstream artifact once, sorted into the three reversibility classes, with the status each artifact holds against a recorded current state and the chain of derivation that reaches it, and the walk reports only and changes nothing. The plan command prints, for the same walk, the candidate compensations each artifact carries and the order a reviewer should consider them in, and it executes nothing. Executing a recall is a separate reviewed act that this tool never performs. The boundary with its sibling is one sentence. Flighttape records the run, badbatch stamps what the run left behind.
